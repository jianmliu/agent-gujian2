# 双人共同参战

沿用用户确认的上一轮建议与本次授权。两名玩家保留各自现有原生队伍。靠近已交战怪物后显式加入，不自动加入，不影响分别挑战其他怪的既有路线。

v5 战斗保存一份敌方 combat 和公共 phase/phaseUntil/strikes，participants 按玩家身份分别保存连击、战斗统计与日志，以及 iframe/guard/action/defense 截止 tick。原生临时战斗上下文由这些组件组合而成，动作结束只回写对应归属。公共攻击时钟只推进一次，到期逐人按各自保护窗口裁决。加入不改变怪物气血、阶段或原参战者任何动作计时。

joinBattle 意图只含 epoch、seq、type、battleId。服务器验证场次仍在进行、玩家尚未参战、当前位置距离怪物不超过2米（浮点容差1e-6）。只向附近且空闲的玩家返回可加入的场次身份。重复或过期加入返回409，不改变成员、时钟或意图序号。处理新加入前先推进到期模拟步，因此加入当下已经发生的攻击不追溯伤害新成员。

断线不移除成员，也不暂停攻击。重连使用原有身份恢复本人战斗。重启恢复所有成员与精确个人截止 tick，清除移动租约，不补服务停止期间时间。每场胜利在一个CAS中标记对应怪物一次、恢复参战队伍气血并释放所有成员；另一怪的场次不受影响。结果记录胜利参战者，未新增物品或经济奖励。

v1-v3先按原规则迁为v4，再升级；v4保留原UUID，将owner与个人字段迁为唯一participants成员。启动只执行一次原子迁移，revision增加一次，角色序号不变。验证公共/个人字段归属、成员不跨场、怪物关联、UUID与时钟，损坏档拒绝启动。

统一验收：显式加入同一UUID、距离/忙碌/重复/过期拒绝、不重置预警、双人同tick出招且冷却互不阻挡、同次扑击分别裁决、断线期间继续计时及重连、双方中途SIGKILL恢复并单次胜利、写失败原子回滚、v4双方分别交战迁移，以及原分别交战完整回归。地图与Three.js两个入口均运行真实双浏览器路线。通过后提交PR，不合并main。
