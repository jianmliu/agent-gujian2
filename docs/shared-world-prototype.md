# 古剑二共享世界原型

两名已配置的玩家共用真实地图的一块固定区域。服务端使用原有地形碰撞处理有限步长的移动。轻量地图展示公开位置、名字和各怪物占用。队伍和战斗详情只返回参战者。

试炼区提供两只可循环刷新的怪物。同一只怪只允许开启一场原有规则驱动的战斗，两名玩家可各自与不同的怪交战，也可在附近显式加入同一场战斗。服务端在模拟步中处理接触；同一步内按轮换的玩家顺序仲裁，未参战者保持独立移动。怪物被击败后保留结算记录。原型战斗使用独立遭遇 ID，避免触发单人剧情奖励。

服务端串行处理请求。使用一行带版本的 SQLite 检查点原子保存两位玩家、怪物和战斗，并以保存序号防止多个宿主覆盖彼此。成功提交后才响应。每次启动更新连接代际，凭据仍绑定到原角色。每人独立意图序号阻止重复结算。

验收从原版地图资源启动真实 HTTP 服务，用两个独立浏览器移动并同时接触，再杀掉服务进程。新进程从同一数据库继续待决战斗并确认一次结算。

## 本地运行

需要 Node.js 22.13 或更新版本，以及相邻 `Open-Gujian2/assets` 下的地形和建筑索引。也可以用 `--assets` 指定该目录。服务只监听 `127.0.0.1`。浏览器的独立网络 Worker 每 200 毫秒续租移动输入或读取公开地图与自己的私有状态。

```sh
npm ci
export GUJIAN2_PLAYER_A_TOKEN="$(openssl rand -hex 24)"
export GUJIAN2_PLAYER_B_TOKEN="$(openssl rand -hex 24)"
npm run host:shared -- --db /tmp/gujian2-shared.sqlite --port 8082
```

在两个浏览器窗口打开终端输出的地址，分别输入甲、乙的凭据。按住方向键或按钮持续移动，松开后停止。重启时使用原数据库和原凭据；新凭据可搭配新数据库开启新试炼。地图上的两只怪物为原型专用遭遇，胜负结束后按模拟时钟刷新；场地限定为原有出生点附近。

## 验收

```sh
npx playwright install chromium
npm run test:shared
npm test
```

可以用 `GUJIAN2_TEST_ASSETS` 指定测试资源目录，`GUJIAN2_TEST_RENDER` 指定 Three.js 和加载器目录。浏览器用例创建独立数据库和两个浏览器上下文，验证接触竞态、私有战斗、未参战者可移动、无凭据访问拒绝、旧代际及重复命令拒绝、待决和已结算战斗在强制终止后的恢复。

战斗原型支持轻击、重击、格挡和闪避。共享战斗由下文的服务端战斗时钟持续推进。

## 双人 3D 入口

用同一条服务启动命令，在两个窗口打开 `http://127.0.0.1:8082/play3d`，分别输入甲、乙的凭据。方向键或按钮提交移动，鼠标拖动旋转镜头，滚轮缩放。3D 与轻量地图可混用，服务端用同一套碰撞、接触和结算规则处理。

3D 页从现有 `Open-Gujian2/js` 复用 Three.js r160、原版角色加载器、骨骼动画和妖兽显示，读取原版 `assets/chars`、`assets/props` 和地形色图。服务端给出试炼区的地形采样和角色高度，客户端在收到的坐标之间做显示插值。甲、乙使用 101、103 模型区分外观。当前每名玩家仍使用原型中独立保存的原有队伍。

使用其他资源位置时，可通过 `--assets /path/to/assets --render /path/to/js` 指定这两个目录。服务按固定模块名单与资源根目录提供读取。原有单人 Three.js 主循环不参与联机规则。

`npm run test:shared` 会分别从轻量地图和 3D 页执行双浏览器用例。3D 还检查实际 WebGL 像素、两份独立蒙皮模型在镜头中的可见性，以及显示位置最终与服务端一致。可用 `GUJIAN2_SCREENSHOTS` 指定已有目录保存实玩与恢复截图。

## 持续模拟与输入停止

服务端用 50 毫秒固定步长推进世界，方向输入的速度为每秒 4 米。重复按键和更频繁的续租不会增加位移。角色碰撞和接触战斗在服务端推进。浏览器的网络 Worker 与 3D 渲染独立，串行发送方向、停止和战斗意图。松键、失焦、页面隐藏或退出都会释放方向；丢失连接时由 750 毫秒的输入租约停止移动。

每一步自动将世界时钟、两人位置、怪物和待决战斗作为一份 SQLite 检查点提交，成功提交后再发布位置。每次宿主调度最多补 5 步，长停顿后从当前时刻继续有限推进。重启恢复最后一份已提交状态和模拟时钟，清除所有方向租约。旧 v1 检查点保留角色、位置和战斗，并从新模拟时钟 0 开始；当前后续保存使用 v6。

世界时钟在等待战斗指令期间继续推进其他玩家；战斗时钟规则见下文。

持续移动统一验收包含不同续租频率下的双人匀速、松键停止、网络中断停止、延迟调度的租约判断，以及旧档迁移。双浏览器分别通过轻量地图和 3D 入口，在持续移动中强制终止宿主，用相同端口重启后原窗口自动同步位置和新代际，旧按键不会续行。随后验证两人接触只开一次战斗、待决战斗中再次重启、继续结算及结算后重启仍只有一次记录。

持续模拟在本机 Node 22.23.3 统一验收通过，共享世界 7 项、原有 normal/pure 各 15 项。长停顿最多补 250 毫秒，因此过载时模拟时间会落后于墙钟时间。原始日志和实玩截图保存在 /Users/jianmingliu/.codex/artifacts/gujian2-continuous-2026-11-08。


## 共享战斗时钟与闪避

共享入口使用 50 毫秒固定模拟步。进入战斗后预警 30 tick（1.5 秒），到期攻击一次；恢复 20 tick（1 秒）后开始下一次预警。攻击不依赖玩家是否发出指令。轻击、重击和格挡沿用原有伤害计算，但不立即触发敌方反击。格挡自身的反击伤害仍在接受指令时计算。单人入口保留原有按指令反击行为，协议调用不能指定共享执行选项。

闪避和格挡各保护 9 tick（450 毫秒），共用 18 tick（900 毫秒）防御冷却。所有玩家战斗动作还共用 6 tick（300 毫秒）动作间隔。冷却从指令成功接受的模拟 tick 开始，不从客户端发包时间开始。旧代际、旧序号、非参战者和冷却中的请求返回 409，不重置截止 tick、不消耗意图序号。处理合法新请求前先推进已到期的服务端模拟步，同一 tick 的敌方攻击先于新防御裁决。

保护区间包含接受 tick、不包含到期 tick；保护刚好在攻击 tick 到期时仍会受伤。提前闪避不会取消预警；只有实际落点被保护覆盖时，才记录一次成功闪避并增加士气。格挡覆盖落点时挡下一次攻击并清除保护。共享战斗的扑击伤害和保护窗口沿用既有数值；当前倒下、治疗和复活规则见生命周期章节。单人入口保留原有气血下限。

v3 检查点保存预警／恢复阶段及截止 tick、保护与冷却截止 tick、攻击次数，以及同一次攻击后的队伍状态。所有改变与世界位置、怪物和结算记录在同一次 SQLite CAS 中提交。提交失败后宿主停止服务，重启从最后一份成功状态继续。服务停止期间不追补战斗时间；恢复剩余模拟 tick。长调度停顿仍最多补 5 步，过载时模拟时间可能落后墙钟。旧 v1/v2 待决战斗在首次恢复时建立完整预警或恢复阶段，原本没有可恢复的战斗时钟，因此不推算旧预警已经过去的时间。

地图页和 3D 页显示服务器返回的预警、恢复及闪避剩余毫秒，冷却期间禁用相应动作按钮。显示每约 200 毫秒随状态更新，实际保护和命中以服务端 tick 为准。另一名玩家的移动不因战斗暂停。

验收覆盖保护到期的精确边界、命中时成功闪避、重复序号及新序号防御冷却、格挡消费、非参战者探索、旧档升级、损坏时钟拒绝和提交失败后的单次恢复。两个真实浏览器入口都在闪避仍有效时 SIGKILL 宿主，从同一数据库恢复，继续战斗并在结算后再重启，验证只结算一次。

本批在 Node 22.23.3 与 Chromium 下统一验收通过，共享测试 17 项，原有 normal/pure 各 15 项。独立代码复核发现的原生协议执行选项泄漏已修复并加入回归，复核无剩余问题。本地日志和 3D 恢复截图保存在 /Users/jianmingliu/.codex/artifacts/gujian2-battle-clock-2026-11-08。


## 多怪物与并行遭遇

v4 将世界中的单例怪物与战斗改为 `monsters` 和 `battles` 集合。`trial-1` 保留原有中央位置，`trial-2` 位于同一区域经过物理检查的另一条可达短路线上。两只怪有独立名字、位置、占用和结算记录。该批提供两名固定玩家、两只一次性怪物，各场起初只有一名参战者；后续共同参战规则见下节。

新战斗使用持久化 UUID，怪物实例 ID、敌人内容 ID 与战斗实例 ID 分开。战斗结束后怪物仍保留战斗 ID 和单次结算记录。意图必须匹配当前玩家拥有的活动战斗，因此另一名玩家的指令、已结束战斗的指令，以及同一玩家上一场战斗的指令都不能操作新战斗。公开怪物列表只显示怪物状态，不公开另一人的气血或保护窗口。可加入场次身份通过附近空闲玩家的加入候选单独返回。

每个世界步按稳定怪物顺序推进所有活动战斗，然后轮换玩家顺序仲裁移动接触。同一只怪在同一步内最多被一人占用。沿实际移动段选择最早接触的可用怪物；已占用的怪物不阻挡另一名玩家去探索或挑战另一只怪。两名玩家使用独立的原生战斗引擎上下文，各自读取自己的队伍和待决战斗。预警、伤害、保护窗口和冷却规则沿用上一批。

两场战斗的时钟、队伍状态和世界位置在同一个 SQLite CAS 中提交。失败时双方候选结果都不发布，宿主停止服务；重启后继续未提交的模拟步。胜利只结束对应战斗并标记对应怪物，另一场继续计时。先结束战斗的玩家可以恢复探索。

v1/v2/v3 存档启动时原子迁移为 v4，保存序号增加一次，角色意图序号不变。中央怪的可用、待决或已结算状态全部保留，第二只怪初始可用。v3 的绝对截止 tick 与已接受的动作效果原样保留；v1/v2 按原规则建立缺失的战斗时钟。迁移生成的 UUID 在启动返回前写入，立即再次重启也不会变化。启动会验证怪物与战斗的双向对应、唯一身份、唯一参战者和有效时钟；损坏关联拒绝恢复。

地图页和 Three.js 页分别展示每只怪，自己的战斗面板显示目标名字。统一实玩路线覆盖争抢中央怪、未参战者接触第二只怪、双方分别出招、两场计时中途 SIGKILL、恢复原战斗身份和剩余 tick、先结束一场并继续探索、再结束另一场及最终重启。各怪的开启和结算次数均应为一次。

本批于 2026-11-08 在 Node 22.23.3 与 Chromium 下统一验收通过，共享测试 35 项，原有 normal/pure 各 15 项。旧版三种存档的可用、待决和已结算状态共九种迁移组合均通过；双场同时命中写失败后的恢复和损坏关联拒绝均通过。独立代码复核无剩余问题。日志、诊断失败记录和双方 3D 截图位于本机 /Users/jianmingliu/.codex/artifacts/gujian2-parallel-2026-11-08。


## 双人共同参战

两名玩家可在同一只怪附近显式加入同一场战斗。第一个接触者创建场次；另一人距离怪物不超过 2 米时，地图和 3D 页显示「加入」按钮。仅移动到附近不会自动参战，仍可离开并挑战另一只怪。服务器验证当前场次、距离和空闲状态；已在其他场次、重复、过期或携带额外参数的加入均被拒绝，不消耗角色意图序号。加入候选只向附近空闲者提供。

v5 保存一份敌方气血、护盾和公共预警／恢复时钟，按参与者分别保存队伍、连击、日志、统计和保护／冷却截止 tick。两人可以在同一模拟 tick 出招，自己的动作冷却不阻挡同伴。怪物每次扑击只增加一次公共攻击次数，但逐人裁决闪避和格挡；一人的保护不覆盖同伴。加入不恢复怪物气血，不重置公共阶段，也不改变原成员的保护窗口。新请求先推进到期模拟步，所以已经发生的扑击不会追溯命中新加入者。

浏览器断线不移除成员，服务继续推进两人的战斗。使用原凭据重连会直接恢复本人参战身份，无需再次加入。服务进程重启则从最后提交的模拟 tick 恢复公共时钟和每人的保护／冷却，不追补服务停止期间时间。每位玩家仍控制自己的现有原生队伍，当前倒下与治疗规则见生命周期章节。

一次胜利在同一 SQLite CAS 中结束该场次、记录单次结算及胜利参与者、恢复参战队伍气血，并同时释放两人的控制权。竞速发送的另一个终结指令会因场次已经结束被拒绝。加入或胜利写入失败时，未提交的成员、气血和结果都不会发布，重启后从最后成功检查点继续。该共同参战批次未增加经济奖励、失败、撤退或复活，后续生命周期规则见下文。

v1–v4 均可原子升级为 v5；v4 保留原 UUID 和精确截止 tick，将原 owner 的个人字段移入唯一参与者组件。两场分别交战的旧档保持两场独立状态。迁移在启动返回前完成，角色序号不变。启动验证成员不能跨场，公共状态不能混入个人字段，未结束的怪物不能携带胜利结果。

界面显示自己的参战成员、目标和保护窗口，不显示同伴的私有队伍与冷却。加入按钮在候选未变化时保持同一个 DOM 节点，避免状态轮询丢失点击或键盘焦点。3D 动作动画按自己的动作截止 tick 触发，避免同伴扣除怪物气血时让自己误播放攻击。

验收保留两人分别交战路线，并在轻量地图及 3D 页各增加共同参战路线。包含附近显式加入、独立出招、关闭一个浏览器上下文后战斗继续、同身份重连、双方参战中途 SIGKILL、恢复同一场次与精确个人窗口、共同胜利、结算后再次重启仍只有一次。加入控件还检查跨快照焦点和跨轮询长按点击。定点测试覆盖双方错开闪避、到期扑击先于加入、加入和胜利写失败回滚，以及 v4 双场精确迁移。

## 胜负、复活与怪物刷新闭环

共享战斗允许气血归零。每名玩家按整支在队队伍判定倒下，仍有存活角色时由存活角色担任领队，倒下同伴不参与输出。战斗中的自动治疗只恢复存活角色，倒下的阿阮不能治疗。一名玩家全队倒下后不能移动、攻击或加入，另一名参战者继续；全员倒下时该场原子结算为战败。原生单人入口保持原规则。

倒下者可点击「复活并返回出生点」，按本次倒下身份复活至各自原出生点，恢复在队角色气血，脱离仍在进行的旧场次。复活不影响其他成员的敌方时钟。随后可以正常探索或靠近并显式参战。胜利恢复仍存活玩家的整支队伍，已全队倒下的玩家须手动复活；没有新增经济奖励或主动撤退。

胜利与战败均让怪物进入200 tick（10秒模拟时间）的等待刷新状态。截止时只刷新一次并增加代数。新一轮接触创建新的战斗UUID；累计开启、结算和刷新计数分别保留，最近一场结果记录其身份、代数、胜负、成员与结束tick。刷新后仍保留该结果，避免无限累积历史。旧战斗指令无法影响新一代，本次倒下的复活身份也不能在下一次倒下复用。
